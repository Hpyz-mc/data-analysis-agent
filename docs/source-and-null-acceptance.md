# 选表、字段与空值：定向修复验收

日期：2026-10-09。仅更新当前项目的 API/UI，未重建数据库、删除数据卷或修改原有业务表。没有提交或推送 Git。

## 改动与接口

- `POST /api/v1/analyze` 与 `POST /api/v1/analyze/stream` 新增可选 `source_table`，例如 `{"question":"查询销售额合计","source_table":"public.sales"}`。不传时兼容显式表名、原有会话范围及唯一可用表；多表歧义需澄清。
- 数据源同时限制计划和实际 SQL，检查 CTE 内的物理表，而非误把 CTE 别名当作外部表。两次规划仍不符合选表约束时停止，不查询错表。当前入口只支持一张业务表，不新增跨表连接能力。
- 问题明确指向的表与界面选择冲突，或所选表不可访问时，在模型调用前澄清。切表丢弃旧表的历史参考、指标、时间和筛选，历史记录本身不删除。
- 响应和历史增加可选 `source_table`，存入已有 artifacts，便于没有结构化范围的查数记录恢复选表；旧历史字段为空仍兼容。不需要 schema 迁移。
- “用户、库存、退款”等不再因为主题本身被拒绝。实际不存在的指标在范围校验时澄清；用户明确指定缺失字段时，前置拦截，防止模型用其他指标替代。口语业务指标不是字面字段名，仍交由范围规划，不做全局关键词拒绝。
- 缩尾和截尾显式保留 NULL；增加有效样本数与截尾后保留数。没有有效数值时不填零；样本存在但截尾全部排除时可为零，并解释原因。固定异常值聚合报告由程序生成，区分缩尾与截尾，不额外消耗报告模型调用。

## 本地验证

- 后端：`python -m unittest discover -s tests -q`，160 项通过，模拟模型/数据库，不产生模型费用。
- 前端：20 项通过；TypeScript 检查与 Docker 内生产构建通过。
- PostgreSQL：用 READ ONLY 事务和 VALUES 表达式运行实际生成的 SQL，不读取业务表。`10、20、NULL` 的原始/缩尾合计均为 30，有效数 2；无 NULL 的 `10、20` 同样为 30。全部 NULL 或空查询的三个合计均为空、有效数为 0。两条样本均在分位区间外时，截尾合计 0、保留数 0。
- 明确缺失字段的前置修复，使用下面第 6 轮的原问题做本地完整图回归，确认 `requires_clarification=true`、`finished=false`，模型与 SQL 均未调用。

## 六轮真实前端验收

从 `http://127.0.0.1:8501/` 上传两份新建的合成 CSV，各 3 行，列为 `订单日期、销售额、用户数量`。A 的销售额为 `10、20、空`，用户数量为 `1、2、3`；B 为 `100、200、空`，用户数量为 `4、5、6`。只有合成查询结果发送到配置的 DeepSeek，不对原有业务表做模型测试。

| 轮次 | 内容 | 实测及判定 |
|---|---|---|
| 1 | A 表销售额合计 | 30；实际 SQL 读取 A，完成 |
| 2 | A 表用户数量追问 | 6；查询真实中文字段，完成，没有主题误拒绝 |
| 3 | A 表 1%/99% 缩尾 | 原始和缩尾均为 30；模型误将“截尾保留 0 条”标成“缩尾保留 0 条”。计算通过，文字未完全通过 |
| 4 | 切换 B 表后查金额 | 300；实际 SQL 读取 B，无旧表筛选，新会话，完成 |
| 5 | B 表缩尾追问 | 300；修复后程序说明“缩尾保留 2 条、截尾保留 0 条”，1%/99% 边界 101/199；完成 |
| 6 | 不存在的退款字段 | 回答没有退款金额，但仍查询了销售额；此轮未通过“不得替代查询”要求。随后加字段前置拦截，本地回归通过 |

第 6 轮原题：`查询当前表的退款金额合计。如果没有退款金额字段，请明确说明缺少这个字段，不要用销售额代替。`

共发送 6 次前端请求，没有追加付费重测。提供方报告总 Token 为 58,525，共 13 次模型调用；第 5 轮仅一次规划调用，说明由程序生成。两段验收会话各保存 3 轮。旧会话未删除，刷新后可从左侧加载历史。

## 验收边界与保留数据

- 不能把本次记录称为“六轮最初全部通过”。第 3 轮的问题已在第 5 轮前端复核修正；第 6 轮前置校验修复仅做了本地回归及运行容器的零模型检查，未发送第 7 个前端问题。
- 旧回答保留当时的真实执行结果，不回写或改造历史报告。加载 A 会话时，仍能看到修复前第 3 轮的误标签；B 的第 5 轮是修复后的正确说明。
- 两份合成表 `user_data_agent_acceptance_a_20261009_01`、`user_data_agent_acceptance_b_20261009_01` 和验收会话保留供复核，没有执行清理或删除。
- 任意口语指标映射、复杂多目标覆盖和报告逐句正确性仍不作保证；选表硬约束不是通用语义正确性证明。没有扩大调用预算或新增分析功能。
