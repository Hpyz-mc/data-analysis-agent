# 多层下钻与追问演示

打开 http://127.0.0.1:8501，先从侧栏加载电商演示表，再新建会话。以下问题在同一会话中依次发送，用户无需填写 ID。

1. `请分析 demo_ecommerce_orders 中 2026 年 2 月销售额为什么比 1 月下降，按渠道归因，并展示贡献图。`
   - 两期总额分别是 666,000 和 652,300，净变化 -13,700。
   - 线下门店 -37,000，线上商城 +15,300，第三方平台 +8,000。
   - 正负贡献柱状图应与这些变化额一致；可以点击“线下门店：按品类下钻”。
2. `线下继续按品类看，并展示贡献图。`
   - 当前范围保留 1 月和 2 月，新增“渠道=线下门店”，维度改为品类。
   - 该层总额是 200,000 和 163,000，净变化 -37,000。
   - 电脑 -20,350（55%），家电 -11,100（30%），服饰 -5,550（15%）。
   - 贡献率针对线下这一层的净变化，不能当作总体净变化贡献率。
3. 点击“查看当前范围的月度趋势”，或发送：`沿用当前表、指标和筛选条件，查看覆盖两个比较时期的月度走势，并画折线图。`
   - 范围仍为线下门店，月度值为 200,000 和 163,000，变化率 -18.5%。
4. `那改为3月比2月，仍看线下，按品类归因并画图。`
   - 当前范围应改为 2 月和 3 月，线下筛选保留；所有数字重新查询。
   - 两期总额为 163,000 和 190,000，净变化 +27,000；电脑 +14,850、家电 +8,100、服饰 +4,050。
5. `继续按商品下钻。`
   - 演示表没有商品字段，应提示无法继续按商品下钻，不能虚构商品明细。
6. `那线下这两个月合计多少？`
   - 只查询 2、3 月线下合计，应为 353,000；不强制执行归因和绘图。
   - 临时查数不会覆盖原来的两期比较上下文，后续可以继续下钻。

重新打开左侧历史会话，检查每轮图表和当前范围是否恢复。重启 API 后继续同一会话，范围仍从数据库读取。

以上链路于 2026-09-30 使用本地 PostgreSQL、模型与容器 API 实测；归因明细与独立总额核对一致，缺少商品字段时未执行查询，历史记录与图表可读取。

这是一份合成演示数据。维度贡献解释数值变化的组成，不能证明供应链或其他因素造成了变化。单表归因要求可加总指标；均值、比率和跨表因果分析属于尚未实现的范围。
