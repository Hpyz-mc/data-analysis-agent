# 执行入口与预算收尾修复（2026-10-04）

## 本次解决什么

不提高 `LLM_MAX_CALLS` 默认值（仍为 6）。订单量、客单价和供货辅助查证原本就由程序生成 SQL 和计算参数，本次不重复实现它们；修复的是分析入口可能落回自由决策、模型调用预算收尾和失败可观察性。

1. 趋势、比较、诊断及明确要求的辅助指标分析必须提交经过字段、指标、时期和筛选验证的 `analysis_context`。模型遗漏结构化范围时，仅允许一次规划补正；第二次仍不合格则停止，不执行猜测 SQL，不伪装成用户业务范围不清晰的已完成澄清。
2. 有效范围进入固定流程：程序查询独立总额、明细及适用的辅助数据，执行计算与核验、生成要求的图表，最后才让模型写报告。工具节点不消耗模型调用次数。普通查数和概念问题保留轻量路径。
3. 为最终报告保留最后一个模型调用名额。第 6 个名额不能再用于规划或自由工具决策；此前的网络/格式重试仍计入预算。Token、上下文和整体时限预算仍独立生效，预留名额不是保证报告一定成功。
4. 最终报告阶段不能返回新工具决策；若返回则保留已有结果并标记未完成，不重复调用模型。
5. 中途模型预算、网络或报告失败时，只要已有可用的未截断查询行，就返回程序生成的部分结果（`finished=false`），保存为 `incomplete`，不重跑工具，不将半截正文当作正式回答。尚无可用数据时仍返回错误。主动关闭流式连接不会被转成成功。

## FastAPI 可查看的字段

`POST /api/v1/analyze` 的结果/分析错误响应，以及 `/analyze/stream` 的终端 `result`/`error` 事件新增 `diagnostics`：

- `route`：`scoped` 固定流程、`lookup` 查数、`concept` 概念或 `unplanned`。
- `planning_attempts`：语义规划次数（不等于底层请求次数）。
- `stage`、`stopped_at`、`last_round`：阶段和停止位置。
- `stop_reason`：如 `planning_limit`、`report_reserved`、`model_call_budget`、`connection_error`、`timeout`、`invalid_report`、`tool_error`。
- `status`：`completed`、`clarification`、`incomplete`、`failed`。
- `tools`：执行轮次、工具类型、结果状态、操作类型及查询行数；不复制 SQL、数据值、问题正文或原始异常。

`usage.calls[].phase` 区分 `planning`、`decision` 和 `report`，格式重试与网络重试仍有原有记录。未获得供应商实际 Token 数据时保留未知，不能把估算当账单。

成功、部分完成与失败的安全诊断摘要写入会话已有 `artifacts` JSONB，历史接口也返回该摘要。本次无需修改数据库表定义、权限或迁移旧会话。前端不新增 Token/诊断常驻栏，沿用原有完成/未完成展示。
