- 线下 2 月比 1 月：200,000 → 163,000，变化 -37,000；电脑 -20,350、家电 -11,100、服饰 -5,550。
- 修改时期后，线下 3 月比 2 月：163,000 → 190,000，变化 +27,000；两月查数合计 353,000。

- 回到总体清除了渠道筛选，最终 3 月比 2 月为 652,300 → 702,600，变化 +50,300。

## 发现的问题与建议

1. **按月意图校验不足**：第 1 轮明确要求每月金额，模型计划却将其变成范围合计，程序执行了一次 SUM 查询。回答诚实说明未取得月度拆分，但仍返回 `finished=true`。建议增加“用户所需粒度—计划—实际结果”的一致性检查，缺少粒度时不能标为完成。
2. **模型格式与计划校验产生额外消耗**：第 4、12 轮发生格式重试；第 16 轮没有格式重试却调用了 5 次模型。优先优化结构化决策和计划反馈，比单纯缩短回答更直接。
3. **不能把成本变化都归因于历史增长**：前 5 轮平均 14,512.4 Token，后 5 轮平均 17,368.8 Token，约增加 19.68%，但两组题型与调用次数不同，这不是同题控制实验。第 19 轮仍只消耗 12,355，未呈现逐轮单调上涨。
4. **历史已有上限**：目前只读取最近 5 个已完成问答，并限制约 6,000 字符。该限制不是 Token 预算，仍建议后续基于结构化上下文精简历史长回答。
5. **证据引用约束仍需加强**：历史数字只能帮助理解，不能替代本轮证据；本次测试不对所有回答逐句做自动事实审计。
